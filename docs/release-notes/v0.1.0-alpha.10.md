# Agentic Evidence Lab `v0.1.0-alpha.10`

Alpha.10 is a method-only release of the Completion Integrity measurement
foundation. The exact Git tag, exact-SHA CI run, release manifest, verified
assets, and GitHub prerelease establish publication; this note alone does not.

It adds no positive agent-effect result. Synthetic fixtures establish bounded
contract behavior only. No scored model call, admitted v2 task population,
runtime-isolation observation, reviewer-remediation experiment, independent
replication, or downstream outcome is claimed.

## Why this release exists

Alpha.9 found no reduction in false completion from the exact tested prompt
policy. Its retained evidence can recompute that null, but cannot distinguish a
redundant instruction from absent policy enactment or an enacted but ineffective
process. Alpha.10 repairs that named measurement defect prospectively without
rewriting the alpha.9 result.

## Released instruments

### Observable enactment

A family-local pure policy separates four non-compensating facets:

- binding to the exact policy bytes;
- materialization of the required ledger;
- normalized check evidence after the final relevant change;
- terminal reconciliation with the ledger and checks.

Missing historical instrumentation is `not_assessable`; unsafe or inconsistent
input is `invalid`. Event labels remain caller-provided facts, not proof of
cognition, causal mediation, or real harness capture.

### Terminal claims

A second pure policy keeps three axes distinct:

- truth: `complete`, `incomplete`, or `uncertain`;
- progress: `continuable`, `awaiting_clarification`, or
  `externally_blocked`;
- extent: exact verified, failed, and unresolved requirement counts.

Reporter submissions are compared with evaluator-owned frozen truth and exact
trajectory/evidence hashes. Closed JSON and hash checks do not prove that the
runtime actually removed reporter access to tools, writes, retries, evaluator
bytes, or remediation authority.

### Task supply

The prospective `0.2-development` task-supply contract separates lifecycle
state from study role and adds non-compensating gates for:

- exact observable requirements and oracle coverage;
- structurally distinct accepted solutions and semantic mutants;
- deterministic environment checks and root lineage;
- terminal-state challenge cases and blocker-feasibility evidence;
- evaluator custody and sealed scored evaluators;
- sacrificial qualification and untouched confirmation;
- a hash-bound, pack-specific power or precision rationale.

The private 32-design inventory is authoring capacity, not a powered task
population. `pending_pilot` blocks admission and scored freeze; repeats,
paraphrases, ports, calibration cases, and weak clones do not increase
independent `n`.

The release also validates the existing public result graph, recomputes the
alpha.9 null, verifies released evidence against its owning tags, inspects wheel
and source archives, and exercises the offline Docker runner. These checks are
repository and computation evidence, not a rerun of private hosted calls.

## Compatibility and privacy

Alpha.10 changes none of the five Contract v0 schemas or previously released
evidence bytes. Exact active tasks, evaluators, reference solutions, mutants,
raw attempts, authentication, canaries, and personal filesystem paths remain
outside Git and release archives.

The new family-local schemas remain explicitly developmental. They are not a
generic task registry, mediator framework, or compatibility promise for other
benchmark families.

## Next evidence

The next empirical step is to implement an owner adapter, qualify the first
private task roots, obtain pilot inputs for a defensible sample-size plan, and
freeze a separately authorized prospective study. Negative, harmful,
inconclusive, and protocol-invalid outcomes remain publishable states.
