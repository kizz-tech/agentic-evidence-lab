# Agentic Evidence Lab `v0.1.0-alpha.11`

Alpha.11 is an empirical integrity release. It exercised the alpha.10
Completion Integrity method against real Codex CLI calls and retained the
result the protocol produced: the activation adapter is **not qualified** for a
larger pilot.

The exact Git tag, exact-SHA CI run, release manifest, verified assets, and
GitHub prerelease establish publication. This note describes the intended
release content; it is not publication proof by itself.

## Result

Activation v1 stopped before model generation because the provider rejected a
frozen response-schema keyword. V2 was separately repaired, qualified,
preregistered, and executed once. Its six-cell schedule stopped after two
terminal cells:

- `CI2-PY-01-E0`: valid executor, but the observable chain was incomplete and
  its terminal claim disagreed with deterministic truth;
- `CI2-PY-01-B0`: evidence identity and isolation checks passed, but the full
  claim wrapper was structurally invalid;
- four remaining cells: unrun under the frozen stop rule;
- retries and resumes: zero.

The public disposition is `protocol_invalid / revise_activation_adapter`. Zero
valid reporter calls means there is no B0/T1 accuracy or effect result.

Retained private evidence shows that the B0 model content matched frozen truth,
while an owner-generated bare hexadecimal attempt identifier violated the
terminal-claim grammar. The public graph recomputes the protocol-invalid
decision but cannot independently reconstruct that withheld causal diagnosis.

## Repairs for future observations

- Adapter attempt IDs are now valid by construction as
  `attempt:<32-hex-digest>`.
- A regression exercises the complete generated-ID → frozen-truth → reporter-
  submission → terminal-assessment path, rather than only model JSON schema.
- The activation materializer emits record-centric `artifact` claims when a
  protocol has only `structurally_valid` evidence; completed activation remains
  eligible for `workflow` claims under `runtime_conformant`.
- Public projection `0.6` introduces `not_assessed_current` so a prospective
  run without a preregistered Study Quality Profile is neither mislabeled as
  historical nor certified retrospectively.

The materializer claim-class repair is a disclosed post-run publication repair.
It changes no observation, run state, measurement, terminal decision, or frozen
historical source hash.

## Why no immediate v3 rerun

The v2 task and output were observed. Repairing the adapter and rerunning the
same cell in this release would be outcome-conditioned adaptation, not
prospective validation. Alpha.11 therefore publishes the failure and source
repair without claiming the repair has empirical support.

Alpha.12 must use a new protocol revision, new sacrificial roots, new raw root,
new preregistration, full-wrapper qualification, and a prospective Study
Quality Profile. Only a passing activation can admit a larger Codex-only pilot.
Cross-model and cross-harness comparisons remain deferred until the Codex
method stops confounding adapter defects with system differences.

## Release gates

The release candidate is required to pass Python 3.11–3.13 lint, format, unit
and contract tests; deterministic result regeneration; exact Git-proof audits;
frozen-evidence checks; clean-wheel installation; source/wheel archive privacy
verification; and Docker isolation, task-pack, Codex image, and reporter-
boundary smoke tests. Hosted scored calls are not rerun by CI.
