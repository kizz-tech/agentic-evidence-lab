# Agentic Evidence Lab `v0.1.0-alpha.8`

Candidate state: locally prepared; a note file is not proof of a tag, CI run,
package upload, or GitHub release.

Alpha.8 is a methodological correction before the next scored study. It makes
the public product claim-first: a reader sees the bounded decision and exact
selected claims before technical receipt metadata, while the underlying
Contract v0 evidence remains unchanged.

Because alpha.6 and alpha.7 were development lines rather than external
releases, this candidate also carries forward their prospective lifecycle,
Study Quality Preflight, explicit reproduction facets, and roadmap work. The
latest public release may therefore advance directly from alpha.5 to alpha.8.

## Claim-first decision method

The new [AEL Method](../method.md) follows one sequence:

```text
question → claim → admitted design → frozen comparison → observations
         → evaluated claim → bounded decision → action → outcome/revalidation
```

Claim admission is no longer computed from numeric ranks. Each selected claim
must satisfy an explicit receipt evidence-state predicate plus its comparison
design:

- factor-causal and model-only claims require a controlled-factor comparison;
- model-only claims additionally require a model-only treatment class;
- operational-stack claims require an operational-stack comparison;
- causal and stack claims require at least one claim-local Measurement Set ref;
- transfer requires a matching evidence state and a claim-local measurement
  linked to a run on a transfer task pack;
- outcome requires matching evidence and a claim-local outcome measurement,
  while an independently verified outcome also requires independent ownership;
- external use, payment, and downstream outcome cannot silently authorize a
  different causal or generality claim.

Contract v0 `evidence_level` remains in machine output as **receipt evidence
state** compatibility metadata. It is not a grade or total order.

The admission relation now lives in the pure `ael.method_policy` module and is
covered independently from file loading and Markdown generation. The raw
receipt renderer uses the same **receipt evidence state** / **claim class**
language; existing JSON keys and frozen historical Markdown remain unchanged.
Every selected claim reference is classified as a Measurement Set row, a safe
public sidecar, or an explicitly opaque historical reference. Sidecar SHA-256
values enter the generated source inventory. Every selected claim requires at
least one public binding; causal, stack, transfer, and outcome claims require a
Measurement Set binding. This establishes graph binding, not semantic
entailment.

## Public result projection 0.5

Generated cards and the Results Index now lead with:

1. bounded decision and reversal trigger;
2. decision-governing claim statements, classes, and statuses, followed by
   additional selected workflow/artifact disclosures;
3. exact comparison and task scope;
4. observed outcomes, cost, valid-repeat coverage, and uncertainty presence;
5. prospective design preflight;
6. lifecycle, replication, independence, freshness, and technical evidence.

Valid repeats are derived per retained task-condition cell from Run Records.
Uncertainty disclosure is derived from Measurement Sets. These are observed
facts, not a synthetic reliability score. Study Quality remains a pre-run
declaration and is shown as **Study design preflight** with planned reliability
coverage.

The `0.5` profile requires `decision_claim_ids` to be a non-empty subset of
`claim_ids`. This stops a supported integrity claim from visually cancelling a
contradicted effect claim in the index; it does not create or rewrite receipt
claims.

The profile and projection identifiers are:

- `ael.public-results/0.5`;
- `ael.publication-projection/0.5`.

## Publication architecture hardening

The public projection keeps its existing API but separates the reasons it must
change:

- `ael.result_core` owns strict JSON/path handling and one fail-closed
  `SourceLedger` for every dereferenced source byte;
- `ael.result_verification` supplies one immutable audit-adapter registry to
  both the CLI and projection;
- `ael.result_rendering` is deterministic and cannot read or authorize
  evidence;
- architecture tests preserve the inward dependency direction and the pure
  Method Policy boundary.

This is not dynamic plugin loading, a service graph or Contract v1. It removes
duplicate adapter dispatch and makes previously implicit provenance accounting
an executable invariant.

## Compatibility and evidence boundary

Alpha.8 changes no Contract v0 schema or historical evidence byte. It runs no
new scored model calls and does not retrospectively certify existing studies.
All current result families remain maintainer-evaluated, have one valid
observation per retained task-condition cell, report no measurement intervals,
and lack independent replication. The projection cannot infer a completely
absent planned cell from Run Records alone.

The release does not prove that AEL improves agent systems or reader decisions.
Its next falsifiers are a prospective profiled study, a completed downstream
follow-up, a role-separated reproduction, and a reader comprehension test.

## Verification before publication

Publication still requires the exact candidate commit to pass the full CI
matrix, clean-wheel install, deterministic result regeneration, frozen-artifact
guard, archive verification, and Docker isolation smoke. Release artifacts must
be built from and linked to that exact commit. A local pass alone is not a
published release.
